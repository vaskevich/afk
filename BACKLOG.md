## Review 2026-09-15: principal security engineer

A pass over the authorization model, ingest and read abuse paths, secrets at rest and in transit, the installer, the deployed headers (checked live against `afk.osv.im`), the container, the bucket key, and the self-host story, judged for a one-person deployment on a nano node whose sessions are readable by anyone holding the URL. Ordered by risk reduced per hour of work; "(before launch)" marks what should land before the project is announced. Items already open above (rate limiting session creation, tagged releases with an out-of-band checksum, the redaction and delete items) are not repeated.

- [ ] [security] (before launch) Cap bytes per session, not just frames: `AFK_MAX_FRAMES_PER_SESSION` (15 000) was sized for 350-byte system frames, but a `processes` frame with ten 512-char commands is ~6 KB and a `run` frame with a full tail ~8.5 KB, so one anonymous `POST /api/sessions` plus ~120 max-size 1 MiB batches puts ~130 MB of strings into a 512 MB node and three such sessions crash it; count accepted NDJSON bytes per session in `SessionStore.ingest` (`packages/server/src/store/sessions.ts`, new `AFK_MAX_BYTES_PER_SESSION`, default 8 MiB, an hour of every collector with headroom), answer 410 past it like the frame cap, expose it in `GET /api/stats`, and set `NODE_OPTIONS=--max-old-space-size=384` in `infra/deploy.sh` so the runtime and the admission math agree instead of the container being OOM-killed
- [ ] [supply-chain] (before launch) Finish the pin: the `client-macos` job in `.github/workflows/ci.yml` (added after the pinning pass) uses `actions/checkout@v4`, `pnpm/action-setup@v4`, and `actions/setup-node@v4` by mutable tag, and `deploy.yml` gates on the whole of `ci.yml`, so a moved tag runs code in the deploy path; pin the three to full SHAs with the version as a trailing comment (Dependabot then bumps them), and add a top-level `permissions: { contents: read }` to both workflows so the default `GITHUB_TOKEN` cannot write (the deploy job's own block stays)
- [ ] [privacy] (before launch) Keep session pages out of search engines: a share URL pasted in a public issue or chat is fetched by crawlers and then indexed with the hostname, the ten busiest executable paths, and a failed command's last output; add `X-Robots-Tag: noindex, nofollow` to every response in `packages/server/src/middleware/security-headers.ts` and `<meta name="robots" content="noindex">` to `packages/web/index.html`, with a route test for the header
- [ ] [security] Take the ingest token out of `ps`: `send_oldest_batch`, `end_session`, and `fetch_qr` in `cli/afk` pass `-H "Authorization: Bearer $INGEST_TOKEN"` as a curl argument once a second, and macOS shows every user's process arguments, so on a shared Mac the `chmod 700` on `~/.afk` protects nothing another local user cannot read with `ps -ef | grep curl` and then use to inject frames (a failing command reported as finished) or end the session; write the header line to `$SESSION_DIR/auth` under the script's 077 umask and pass `-H "@$SESSION_DIR/auth"` (curl 7.55+, every supported macOS), with a test that no curl invocation carries the token
- [ ] [supply-chain] Delay new npm versions: a compromised dependency in the server image reads `AFK_S3_SECRET_ACCESS_KEY` from the environment and with it every session id in the bucket, which turns "unguessable" into "listable" for the whole 7-day window; bump `packageManager` in `package.json` to pnpm >= 10.16 and set `minimumReleaseAge: 10080` (7 days) in `pnpm-workspace.yaml` so a version published hours ago cannot land through Dependabot, `pnpm install`, or the Docker build before the ecosystem has pulled it (pnpm 10 already refuses install scripts, which is the other half of this)
- [ ] [security] Bound read amplification on the public endpoints: `GET /api/sessions/:id/stream` (`packages/server/src/routes/stream.ts`) serializes and replays every frame per connection and holds a listener for as long as the socket lives, with no limit on connections per session or per process, so whoever created one large session (or found one) can open hundreds of streams and spend the node's CPU and egress; cap open SSE connections at 20 per session and 200 per process (constants next to `sseKeepaliveMs`, 503 with `Retry-After` beyond), count them in `GET /api/stats`, and cover it with a stream test
- [ ] [security] Store a hash of the ingest token, not the token: `session.json` in the bucket and on disk (`packages/server/src/store/storage.ts`, `SessionRecord.ingestToken`) holds the write credential in clear, so anyone who can read the store (the bucket key, which lives in the deployment spec, GitHub secrets, and tfstate, or another user of a disk-storage self-host) can write into every live session; keep `sha256(token)` in the record, compare with `crypto.timingSafeEqual` in `packages/server/src/middleware/ingest-auth.ts` (which also retires the early-exit `!==`), and accept either shape for one release so a deploy does not 401 the sessions active at the moment
- [ ] [security] The CSP blocks the dashboard's own theme script: the inline `<script>` in `packages/web/index.html` is not `type="module"`, so Vite leaves it inline in `dist/index.html` (confirmed on the live page) and the deployed `default-src 'self'` policy refuses it, which means a violation on every load, the flash of the wrong theme it exists to prevent, and a standing temptation to add `'unsafe-inline'`; move it to `packages/web/public/theme-init.js` and load it with `<script src="/theme-init.js">` ahead of the bundle (keep `'self'`, never `'unsafe-inline'`), correct the "no violations" note in `packages/server/src/middleware/security-headers.ts` and docs/ARCHITECTURE.md, and add a `web.test.ts` case that the built `index.html` has no inline script
- [ ] [self-host] Give a private server a bind address and a Tailscale recipe: `packages/server/src/index.ts` calls `serve({ port })` with no hostname, so a self-hoster's laptop server listens on every interface including cafe wifi, and there is no shared secret yet (open above); add `AFK_HOST` to `config.ts` and docs/CONFIGURATION.md (default `0.0.0.0` for the container, documented as `127.0.0.1` behind `tailscale serve` or the tailnet IP), create session directories in `packages/server/src/store/disk-storage.ts` with `mode: 0o700` since they hold ingest tokens, and add a "Self-hosting on Tailscale" section to README.md: `tailscale serve` for TLS so the token and share link are not plain http, `AFK_PUBLIC_BASE_URL` set to that https origin, `AFK_STORAGE=disk` with `AFK_DATA_DIR` on persistent disk, and the plain statement that everyone on the tailnet can create and read sessions
- [ ] [client] Never print a server body raw: `create_session` (`die "... $response"`), `send_oldest_batch` (`log "server rejected batch ... $(cat response.json)"`), `log_upgrade_required`, and `fetch_qr` (`cat "$file"`) in `cli/afk` write whatever the server sent to the terminal, so a hostile or MITM'd server (a self-host reached over plain http) can drive it with escape sequences; pass every server-supplied string through one `sanitize_for_terminal` helper (`LC_ALL=C tr -d '\000-\010\013-\037\177'`, the same filter `run_output_tail` already applies to command output) before it reaches `log`, `die`, or `cat`
- [ ] [client] `cmd_stop` in `cli/afk` sends SIGTERM to whatever pid `owner.pid` names after only `kill -0`, so an owner that crashed and had its pid reused by another of the user's processes gets that process killed; check `ps -o command= -p "$pid"` mentions `afk` before signalling (and in `load_current_session`, which trusts the same pid to mean the session is live), with a test using a fake pid file

What was looked at and found sound, so the absence of an item is a judgement: the 22-character base62 id (~131 bits) is validated at the edge with a bounded negative cache, so enumeration and storage-read amplification on unknown ids are closed; the write token is separate, never in a URL, a log line, or the dashboard, and the QR endpoint that renders the share link sits behind it; the deployed headers match the source (`no-referrer`, HSTS, COOP/CORP, `nosniff`, `X-Frame-Options: DENY`, `frame-ancestors 'none'`), so a share link is not leaked by Referer and cannot be framed; the dashboard renders every server string through React with no `innerHTML`, and `connect-src 'self'` contains a compromised web dependency; the client executes nothing a server sends (the only `sh` path is the user's own `curl | sh`), follows no redirects, refuses a downgrade from https in the installer, and keeps `~/.afk` at 077; a self-hoster's client references only the origin it was installed from, so a compromised `afk.osv.im` does not reach it; the container runs node as a non-root PID 1 with a digest-pinned base image, deploys go through OIDC with a role scoped to the Lightsail actions it needs and no long-lived AWS keys, and pnpm 10 runs no install scripts; the Lightsail bucket key cannot be scoped narrower than the bucket, so the documented rotation is the right control and the token-hashing item above is what shrinks its blast radius; the `!==` token comparison is not exploitable at 256 bits through a load balancer but is retired by that same item; and gzip on JSON responses is safe because no response that carries a secret reflects attacker-controlled input.

## Wishlist: agents collector (claude / codex)

Parked on 2026-09-15. Investigated and cheap to build (about the size of the
processes collector), but it depends on undocumented tool internals and ships session
names off the machine, so it waits for a deliberate decision.

- What is observable today: Claude Code writes `~/.claude/sessions/<pid>.json` per
  running session (`name`, `cwd`, `kind`, `status`, `version`, `startedAt`, `updatedAt`);
  subagent transcripts live under `~/.claude/projects/<project>/<session>/subagents/`
  and a file modified in the last minute is a working subagent; Codex has `codex` /
  `codex app-server` processes and rollouts under `~/.codex/sessions/YYYY/MM/DD/`.
- Shape: a generic `agents` collector, one entry per agent (tool, pid, name, cwd,
  status, kind, lastActivityAt) plus per-tool working-subagent counts, sampled every 5 s.
- The payoff rule: an agent whose transcript has not changed for 10 minutes while its
  process is alive is almost certainly waiting on a person (permission prompt or
  question). Lean on transcript inactivity, not the `status` string, until its
  vocabulary is confirmed across working, idle, and waiting sessions.
- Privacy: send only the directory basename, make the collector opt-in for hosted
  servers (default on for self-hosted).
- Degrade gracefully when the directories are missing or the file shape changes.
- JSON-heavy in bash; a good first collector for a Python client if that port happens
  (see docs/CLIENT.md).

## Sessions

- [x] Auto-chain a new session when the 1 hour cap is hit, print the new URL -- `chain_session` in `cli/afk`: `afk start` flushes the old queue, creates the successor with `previousSessionId` and the old ingest token as the bearer, prints the new URL and QR, resets sequences, and restarts the sender; the server links both records and ends the old one at that moment; the dashboard links them (`SessionHeader`) and offers the successor once the `end` event arrives (`StatusBanner`). - [x] Mark a session ended after the client goes silent for N minutes -- `SessionStore.tick` ends an active session `AFK_END_AFTER_SILENT_SECONDS` (600) after its newest frame's receipt, `endedAt` at the start of the silence plus that, `ended` emitted; `client.stale` at 60 s stays the early warning. Still to wire: `index.ts` (being rewritten on another branch) must pass `endAfterSilentMs: config.endAfterSilentSeconds * MS_PER_SECOND` into the `SessionStore` options; until then the store runs on its own 600 s default and the variable is parsed but unused
- [x] Multiple processes joining one session: only the first runs the long-lived collectors -- `afk start` refuses while another owner is alive (`guard_running_session`: the running session's URL and a hint), `afk start --force` SIGTERMs it and waits for `current` to go
- [x] Per-collector sampling intervals (not everything needs 1 Hz) -- `sample_once` counts ticks and `due_every` runs a collector every N seconds (`processes` at 5 s)
- [x] Sampling drift: subtract collector runtime from the sleep -- `system_sampler_loop` schedules ticks against a deadline; average rate is 1 Hz, single gaps still vary because stock macOS has no sub-second clock (see the hardening item below)
- [ ] Chaining for an `afk run` that owns its session (no `afk start` running): it still stops at the cap, since its system sampler runs in a subshell and its run sampler and final frame write into the old `SESSION_DIR`; a `chained` marker the run sampler and `cmd_run` re-read `current` on would cover it
- [ ] Joiner re-attach edge cases: a re-attached `afk run` keeps counting its `run:<runId>` sequences rather than restarting at 1 (the server only needs them monotonic; restarting needs `run_sampler_loop` to learn about the switch); it follows `current` only while the owner pid is alive, so an owner that chained and then died leaves the joiner stopped with its queue; a successor that is already at `maxStreams` answers the joiner's batches with 422, which it parks in `rejected/` rather than falling back; the re-attach message is printed by the sender and again by the final flush
- [ ] Chaining with the frame cap: a 410 from `maxFramesPerSession` is chained at once (the sender leaves a `gone` marker), but the batch the server refused and anything queued until the successor exists stay in the old session directory until its cleanup rather than moving to the new one, and a session under `CHAIN_MIN_SESSION_SECONDS` (60 s) old is never chained from `gone`
- [ ] The chain moment is the client's clock from the create response: a machine that sleeps through the cap chains late (the server still links a successor to an expired session), and the sleep is a gap in both sessions either way
- [ ] The first URL does not redirect to the live successor (PRODUCT.md item 5's "one QR valid for the whole absence"): the old dashboard offers a link instead of navigating, on purpose, so a viewer reading the old trace is not moved; a `?follow` query or a server-side hop on `/s/:id` for ended-and-continued sessions would give the phone the other behaviour
